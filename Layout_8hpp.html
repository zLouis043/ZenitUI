Detailed Description

The node class: tree structure, layout pass, style resolution, input dispatch, render orchestration, and scroll handling.

Layout is the single node type in ZenitUI. There is no separate "widget" base class: every visual element is a Layout subclass (either directly, via TLayout<Derived>, or by composition). The node owns or co-owns:

  • Tree structure: parent, children, dirty flags, removal requests.
  • Style subsystem (as style_): resolution, transitions, caching.
  • Animation subsystem (as anim_): imperative and CSS animations.
  • Input subsystem (as input_): hover/press/focus dispatch.
  • Scroll subsystem (as scroll_): offset, inertia, scrollbars.

The public API mirrors the four-pass frame cycle, each function called from Layout::runFrame:

  1. update — input state, style transitions, animations, culling.
  2. measure — compute intrinsic sizes bottom-up.
  3. arrange — assign screen rects top-down.
  4. draw — render with style overlays and clip/effect stacks.

Subclasses hook in via the virtuals (computeIntrinsicSize, renderContent, renderChrome, onLayout, onUpdate, …) rather than by overriding the four main passes, except in rare cases (VirtualView, Canvas, Popup, Tooltip override arrange or draw).

Note
enable_shared_from_this is required: addChild checks weak_from_this() and warns if a node is stack-allocated. Always create nodes through TLayout<Derived>::create or std::make_shared<Layout>.
