Detailed Description

Base node types (Layout, TLayout), per-instance context (UIContext), units, input, and scrolling.

Every UI element is a std::shared_ptr<ZenitUI::Layout>. Always allocate nodes through TLayout<Derived>::create() or std::make_shared<Layout> so shared_from_this() is valid.

Key concepts:

  • Layout strategies: LayoutType::Stack, LayoutType::Vertical, and LayoutType::Horizontal with gap, grow, shrink, wrap, align-items, justify-content, margin: auto, and setVisible(false) (display: none).
  • Units: px, %, vw, vh, pw, ph, auto, and calc() expressions.
  • Portals & stacking: setPortal(true) renders and hit-tests above ancestor clip rects; position + z-index create stacking contexts.
  • Custom components: inherit from TLayout<Derived> and override onBuild(), computeIntrinsicSize(), onUpdate(), or renderContent().

Live examples: 02_layouts · 08_portals · 09_custom_widget

Live examples
  • 00_demo — Flagship ZenitUI showcase: live Dark/Light theming, ZMarkup prefabs & keyed Each, Bindable<T>, UTF-8 TextArea, 10k-row VirtualView, portals, filters, and CanvasLayout.
  • 01_hello_world — Minimal Raylib setup, single Stack root layout, inline styling, and the runFrame/renderFrame loop.
  • 02_layouts — Visual tour of Vertical, Horizontal, and Stack containers with grow, gap, justify, absolute overlay, and wrap flow.
  • 08_portals — Portal-backed overlays (Tooltip, Popup, ContextMenu) escaping parent clipping alongside a full-screen Modal.
  • 09_custom_widget — Custom Rating widget derived from TLayout<Derived>, demonstrating computeIntrinsicSize, renderContent with ::part, pointer/keyboard input, and ZMarkup registration.

◆ ruleMatches()

bool ZenitUI::ruleMatches ( const ThemeRule & r,
const Layout * node,
Vec2 viewport )
inline

true if node matches the full rule selector chain.

The chain is evaluated right-to-left (innermost selector first, matching the node itself), then each ancestor is checked against the previous component in the chain. Any node in between that does not match is skipped (matches the CSS descendant combinator A B). Only descendant combinators are supported; child (>) and sibling (+, ~) combinators are not.

Parameters
rStylesheet rule to test.
nodeTarget node.
viewportActive logical viewport size used to evaluate @media queries.
