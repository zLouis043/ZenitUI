Detailed Description

Resolves, caches, and transitions the style of a single node.

Note
The resolver does not own the node: it is embedded in Layout and receives *this as an argument to every method that needs node state (tag, classes, ancestry, enabled flags, interaction flags). This keeps it stateless w.r.t. the tree shape, which is what allows the cache key to be small and stable.

◆ resolveFor()

ComputedStyle ZenitUI::StyleResolver::resolveFor ( Layout & node)

Compute the fully resolved ComputedStyle for node.

Algorithm:

  1. Build a cache key from theme version, viewport generation, node identity, ancestor state flags, style tag, and class list.
  2. On cache hit, skip the stylesheet walk and apply the state / inline overlays directly on top of cachedThemeStyle_.
  3. On miss, gather matching rules, sort by specificity then order, overlay them, resolve var() references, then call ComputedStyle::from with parent and theme root.
  4. Refresh node.relevantSymbols_ for invalidateIfRelevant.
Returns
The resolved ComputedStyle. The node's style_ is not modified; callers decide whether to assign it to currentStyle/targetStyle.

◆ resolvePendingTransition()

void ZenitUI::StyleResolver::resolvePendingTransition ( Layout & node,
bool instant = false )

Re-resolve the target style after a theme or ancestor change.

Unlike beginStateTransition, this preserves an in-flight transition: if the new target differs from the current target and the node has an active imperative animation, the transition is short-circuited. Otherwise only the properties that changed are marked dirty and the timer is reset.

◆ tick()

void ZenitUI::StyleResolver::tick ( Layout & node,
float dt )

Advance the state transition by dt seconds.

Called every frame while transitionTimer < 1. Interpolates only the properties whose bit is set in transitionDirtyMask_, using per-property durations from targetStyle.transitions (falling back to transitionTime / ease for properties not listed).
