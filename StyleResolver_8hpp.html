Detailed Description

Per-node style resolution, state transitions and per-part animations.

A StyleResolver lives inside every Layout (as style_). It exposes three responsibilities:

  1. Resolve sparse Style inputs (theme rules + inline overlays) into a dense ComputedStyle, with caching keyed by theme version, viewport generation, and the full ancestor-state vector.
  2. Transition between two ComputedStyle when the node's interaction state changes, interpolating only the properties that actually differ (tracked via transitionDirtyMask_).
  3. Part styles: resolve Slider::track, Checkbox::mark, etc., with their own independent transition state per part name.

The struct deliberately keeps its fields public: Layout, Measure.cpp and Render.cpp are friend structs and read/write them directly to avoid accessor overhead in hot paths.
