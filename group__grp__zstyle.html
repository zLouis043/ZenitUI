Detailed Description

CSS-like style cascade, .zstyle parser, custom properties, and media queries.

Load stylesheets into Theme::get() via ZMarkup::loadStyleFile or ZMarkup::loadStyleString. Resolution follows specificity (#id > .class

Tag), supports descendant combinators (A B), interaction pseudo-classes (:hover, :pressed, :focus, :checked, :disabled), custom properties (--token / var(--token)), @media queries, and structured diagnostics with typo suggestions.

Live examples: 05_zstyle

Live examples
  • 04_animations — Declarative animation channels in .zstyle: state transitions, &\#64;keyframes, and ::part animations.
  • 05_zstyle — External .zstyle stylesheet demonstrating :root custom properties, var(), calc(), &#64;media queries, pseudo-classes, ::part, and transitions.
  • 07_effects — Post-processing with CSS filter chains (blur, drop-shadow, custom sepia via FilterRegistry) vs single-pass shader effects.

Apply one declaration to st.

Handles:

  • --name: value (custom properties) → st.customProps.
  • Values containing var(...) → st.unresolvedProps for late binding.
  • transition / transition-* shorthands and longhands.
  • animation / animation-* shorthands and longhands.
  • filter / box-shadow / overflow / overflow-x / overflow-y.
  • Everything else → applyStyleAttr.

Reports an UnknownProperty warning (or error in strict mode) when applyStyleAttr returns false, with "did you mean" suggestions drawn from getKnownStyleProperties.

◆ applyStyleSheet()

void ZenitUI::ZMarkup::applyStyleSheet ( const StyleSheet & sheet,
Theme & theme,
DiagnosticSink * sink = nullptr,
bool strict = false )

Apply a parsed StyleSheet to a Theme.

Order of operations:

  1. Merge rootDecls into theme.root.
  2. For each rule, build a ThemeRule (selector chain + part + media) by applying its declarations to a fresh Style, then addRule.
  3. For each keyframes block, validate uniqueness (warn on duplicate), sort frames by time, normalize, and addKeyframes.
Parameters
sheetParsed stylesheet.
themeDestination theme.
sinkOptional diagnostic sink.
strictWhen true, unknown properties become errors.

◆ normalizeKeyframes()

void ZenitUI::ZMarkup::normalizeKeyframes ( KeyframeAnimation & anim,
const SourceSpan & loc )

Fill missing properties in every keyframe from neighbouring frames.

CSS animations that declare a property only at the start and end still need all keyframes to hold a value for that property, so that the evaluator can interpolate uniformly. This function fills gaps by copying from the previous keyframe, or from the next if the gap is at the beginning. Emits a logWarn for each auto-filled property to make authoring errors visible.
